# Prices, patches and discount rules

Business rules for money. Prices themselves live only in the database (admin Pricing). (Moved from CLAUDE.md 2026-11-23, unchanged.)

- Prices: see admin Pricing (as of 2026-11-15 live: fan 99, player 115, retro 135; long sleeve fan 110, player 125, retro 149.99; kits 160 fan / 170 player / 180 retro / kids 150; name+number 19.99, patches 9.99 / 8.99 / 7.99 / 6.99 for the 1st/2nd/3rd/4th on a shirt, 3XL +9 / 4XL +12, gift box 34.99, no 3-for-300; delivery north 50, elsewhere 70). **Totals are always rounded UP to a whole shekel** (owner 2026-11-15): `roundUpToShekel()` in the engine (`Quote.total`, `Quote.rounding`) - so website orders, online payments and bot quotes agree - and `roundUpShekel()` for the checkout display (`src/data/pricing.ts`). **PayPal fee** (owner 2026-11-15): PayPal orders (`paypal` and `paypal_me`) pay `payment.paypal_fee_pct` % (5) of the whole order on top - the engine's `paymentFeePct` -> `Quote.paymentFee`, added before the round-up; `requote()` takes it from the order's `payment_method`, so the manual/online starts set the method first and re-price; admin Pricing -> Payment edits it; checkout's PayPal box says only "5% PayPal fee applies" (`checkout.payPalFee`). Delivery 10-20 working days everywhere (owner 2026-11-14; was 7-14). Returns: 14 days, unworn with tags; printed shirts only if wrong/faulty.
- Patches (owner decision 2026-10-26): a shopper picks a SET of patches per shirt from a small photo picker (club shirts up to 2, one per sleeve - except La Liga 2025/26 and 2026/27 shirts, only 1 (owner decision 2026-11-10; picking another swaps it) PLUS one Champions League patch (starball or titles badge) next to it (owner request 2026-11-21: `UCL_SLEEVE_PATCHES`/`countedSleeves()` in patch-limits.ts, used by the picker toggle, `sanitizePatches` and `checkPatches`); national-team shirts up to 3 — World Cup, Peace and Champions badges; the one cap rule is `src/lib/patch-limits.ts`). Some shirts carry their own patch list by product handle (`PRODUCT_PATCHES` in the same file, owner decisions 2026-11-12): Barcelona 1992 retro home = none; Barcelona 2008/09 retro home = old La Liga (LFP) + Champions League ball only, with period art in `PRODUCT_PATCH_ART` (`src/data/patches.ts`; the LFP photo is still missing, so the picker shows only the ball until `public/patches/league-la-liga-lfp.jpg` is added and wired). Priced by COUNT on the shirt, tiered: 1st patch 9.99, 2nd 8.99, 3rd 7.99, 4th 6.99 (owner 2026-11-15; was 12.99 / 9.99 / 6.99) (`Addon.price_tiers`, set in admin Pricing, consumed by `lib/pricing/tiers.ts`). Champions League pieces are sold one by one (owner request 2026-11-12, "remove the all-inclusive"): `champions_league` (starball), `ucl_titles_badge` (trophy with the number of wins - only clubs in `UCL_TITLES_BADGE_CLUBS`, uses their numbered art), `ucl_respect`; the earlier `champions_league_full` set is no longer offered (kept in `PATCHES` only so old carts/orders still read). Extras that don't take a sleeve slot (`CHEST_PATCHES` in `src/lib/patch-limits.ts`): `club_world_cup` = gold FIFA Club World Champions badge, offered only on seasons the club held the title (`CLUB_WORLD_CHAMPION_SEASONS`, researched 2026-11-12), `ucl_final_print` = a Champions League final match print (`UCL_FINAL_PRINTS`, so far Real Madrid 2016/17 Cardiff), and `ucl_respect`; all in `src/lib/patch-eligibility.ts`, each 1 patch on the tiers. Current (non-retro, 2024/25+) shirts (owner request 2026-11-12): no Respect patch, and the plain starball only for clubs WITHOUT a titles badge (Real Madrid 2026/27 = La Liga, 15, Europa League) - `uclStarballOffered`/`uclRespectOffered` in patch-eligibility.ts, enforced by the picker, `sanitizePatches` and `checkPatches`; retro shirts keep every option. Patch ids and which team type each is for live in `lib/orders/rules.ts` (`PATCHES`/`checkPatches`, already shared with the Instagram bot); which ids have storefront artwork and which leagues/clubs they're offered for live in `src/data/patches.ts`; art is `public/patches/*.jpg`.
- Riddle coupon + sale (owner request 2026-11-16): `discount_codes.combines_with_sale` (migration 20261116190000, admin Discounts "Can be combined with the running sale only") lets a code join ONLY the running dated sale code (dates set, for everyone, unlimited = `isSaleRow`); all `RIDDLE*` codes have it. When codes combine, fixed-₪ codes come off first and percent codes are worked out on what is left, whatever order they were typed (`canCombine`/`codeAmounts` in `src/lib/discount-rules.ts`, used by web.ts and CheckoutView, tested). E.g. 2 fan shirts ₪198: -₪50 then 15% of ₪148 = -₪22.20.
- Free-delivery codes (owner request 2026-11-21): `discount_codes.free_delivery` (migration 20261121200000, admin Discounts "Free delivery too") makes delivery ₪0 when the code is on the order - `requote()` reads the order's discount-code adjustment rows (a free-delivery code keeps its row even at ₪0 off) and passes `freeDelivery` to the engine; checkout shows ₪0 the same way. **KV25** = 25% off shirts & kits + free delivery, for everyone, not combinable with any code, until 31 Dec 2026 (ends 31 Dec 22:00 UTC); no start date on purpose, so it never becomes the dated `sale` banner/hero (isSaleRow needs both dates).
- Every discount needs an approval row (DB check), except website discount codes (`kind: 'discount_code'`, the code is its own authority). The bot's own discount limit is 0₪. A code's use is claimed with a compare-and-set (`recordDiscountCodeUse`): cash orders when placed, PayPal/Bit only once paid.
