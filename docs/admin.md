- Overview numbers use Israel days (`src/lib/time.ts`); sales skip cancelled and test-bot (`sim:`) orders. "AI cost today" / the spend cap = `agent_runs` (bot turns) + `ai_usage` (photo checks, post matching; `src/lib/ai-cost.ts`).
- Catalog: the website list is Wadeea's `catalog/store-selection.json` PLUS shirts the owner adds in admin **Products -> Add shirt** (`/admin/catalog/new`, owner request 2026-11-12): he picks team / season / kit (+ player, long sleeve, photos) and every name comes from ONE format, `shirtNames()` in `src/lib/catalog/shirt-names.ts` (EN/AR/HE + handle, matches the existing catalogue). Saved by `addShirt()` in `src/app/admin/catalog-actions.ts`: reuses the existing row for the same team/season/kit (e.g. a supplier listing), else a new row flagged `owner_catalog`/`not_at_supplier`; flag `site_listed` (`SITE_LISTED_FLAG`) is what puts it on the site - `scripts/export-store-catalog.ts` adds every flagged, non-hidden row (newest first) - then the deploy hook. The team and season are TYPED or picked from suggestions (owner request 2026-11-13): a typed team must match one we have (EN/AR/HE name or `teams.aliases`), a typed season goes through `parseSeasonInput()` ("2010", "10/11", "2010-11" -> "2010/11") on both the form and the server. **Products -> Stock** (`/admin/catalog/stock`) toggles `out_of_stock` for any website shirt (`setShirtStock`). Editing the hand-picked file itself is still a code change + `scripts/apply-store-selection.ts`; removing a picked shirt from being live is not (see "Deleting / hiding products").
- Pricing page: the owner edits every price there (shirts, extras, offers, delivery fees/days/area names) + "Approve & publish". Saving updates the live price list (bot + checkout at once) and calls the deploy hook so the website's shown prices follow.
- **Prices live only in the database price list, changed in admin Pricing.** Never hardcode a price in code, prompts or translations: website copy uses placeholders filled from `src/data/pricing.ts`; `src/data/price-list.json` is re-exported from the database on every build (editing it by hand changes nothing).
- Owner photo uploads call `VERCEL_DEPLOY_HOOK_URL` (if set) so the static website catalog rebuilds.
- Discount codes (owner feature 2026-10-26): admin Discounts creates/pauses/deletes codes (percent or fixed ₪ off, optional min order / date range / max uses) in the `discount_codes` table. A shopper can type more than one at checkout, but a code only combines with others when its `stackable` column is set (checked in admin as "Can be combined with other codes") - default false, so a code works alone unless the owner opts it in; `codesCanCombine()` in `src/lib/discounts.ts` is the one rule both the checkout UI and the server enforce. `src/app/api/checkout/discount/check` previews a code; `src/lib/orders/web.ts` re-validates every code, the stacking rule, and the minimum order, then applies each as its own `adjustments` row (`kind: 'discount_code'`) when the order is placed - no owner approval needed, a code is its own authority. A code can be `first_order_only` (owner request 2026-11-10, admin "First order only"): `hasEarlierOrder(phone)` refuses it when that phone already has an order past draft that wasn't cancelled.
