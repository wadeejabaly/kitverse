# Instagram, bot and background jobs

DM bot flow, Inngest jobs, Instagram autopost / riddle / polls, messaging rules. (Moved from CLAUDE.md 2026-11-23, unchanged.)

## Background jobs (Inngest)
- Inngest for background work (`src/inngest/`):
  - one turn per chat burst (5s debounce, shows "seen" + typing while it works, concurrency 1 per chat);
  - 3h follow-up nudge, approval decided/reminder, spend alert;
  - IG post sync every 15 min.
  - Instagram autopost every 5 min (owner request 2026-11-13): publishes the posts/stories in `src/data/ig-schedule.json` (images in `public/campaign/daily/`, Arabic captions) through the Content Publishing API - `src/lib/channels/ig-publish.ts`; once per item via the `bot_settings` row `ig_post:<id>` (failed = owner alert, no auto-retry; delete the row to retry), items >3h late are skipped, pause with `bot_settings` `ig_autopost` = {"paused":true}. Needs the token's `instagram_business_content_publish` permission. After deploying a schedule change, re-sync Inngest from the live domain (`PUT https://www.kitversejerseys.com/api/inngest`, e.g. `fetch` in a browser on the site) - on 2026-11-14 the cron kept running an older deploy's schedule until that sync ("modified": true). Poll stories (owner request 2026-11-14): Instagram's API can't add stickers (polls) to a story, so a schedule item with `poll` {question, options} (the VS stories) is NOT auto-posted - at its time the owner gets a push alert to admin **Instagram -> Poll stories** (`/admin/stories`): save picture, copy question/answers, "Open Instagram", then "I posted it"/"Skip" (`markPollStory`, row status `owner_poll` -> `posted_by_owner`/`skipped`). The schedule (and polls) is generated by the campaign scripts (`daily.py`, scratch), not hand-edited. **Owner decision later the same day: "just post them as is"** - no schedule item has `poll` now (VS stories auto-post, their line reads "reply to the story 💬" instead of "vote 👇"), and the Poll stories nav entry is removed; the page/code stays dormant for future use (add `poll` to an item to bring it back). **Monday riddle** (owner request 2026-11-14): every Monday 19:00 a "مين أنا؟" story (a famous player's full career as a timeline; club colours + initials, never real crests - owner asked for real crests, declined as trademark; background = anonymous generated silhouette, never a real player's photo; KitVerse badge watermark), answer story Tuesday 19:00; first one posted Sat 14 Nov 18:15 (Zlatan, answer Sun 15 Nov), then Mondays 16 Nov - 21 Dec, made harder on owner request ("too easy") - no position hint, less obvious careers: Owen, Crespo, Seedorf, Forlán, Anelka, Eto'o (careers from Wikipedia 2026-11-14); codes are used in date order (RIDDLE1611 for the 14 Nov riddle, etc.), RIDDLE2812 spare. Prize (each person can win at most once a month - owner 2026-11-23, printed on every riddle image under the coupon line; the owner skips repeat winners when picking): first correct DM reply wins a single-use ₪50 code (min order ₪100, 31 days, not combinable) pre-created per Monday as `RIDDLE<DDMM>-xxxx` in discount_codes - the owner picks the winner in the Instagram app and DMs the code. Single-use codes (max_uses set) never become the site banner (`export-store-catalog.ts`). Images `public/campaign/riddle/` (AR auto-posted, HE for the owner); generator `riddle.py` (scratch).

## Messaging customers
- Meta Graph API for Instagram. The system only ever messages customers on Instagram (no automated WhatsApp/Telegram to customers). Exception the OWNER sends himself (owner request 2026-11-14): the admin order page's "Message on WhatsApp" card (`src/app/admin/(app)/orders/[id]/whatsapp-card.tsx`, text from `src/lib/orders/whatsapp-text.ts`, tested) builds a thanks+tracking / being packed / out for delivery / delivered message (first name, order number, the customer's `/o` link, estimated arrival dates, cash-on-delivery amount) and opens it with a wa.me link in his own WhatsApp Business - he presses Send; nothing is sent by the server. Language: Hebrew if the name is written in Hebrew letters, else Arabic (`waLangFor`; switchable on the card). The link carries the same language (`/o/<token>?l=ar|he|en`): the customer order page `/o/[token]` is now in Arabic, Hebrew or English (`src/app/o/[token]/strings.ts`; without `?l` it uses the language the buyer checked out in, `customers.preferred_language`). Never the carrier or its tracking number. Owner alerts come from the admin (in-app and web push, `public/sw.js`), plus the optional WhatsApp order alert to the owner's own number (see below).

## Bot flow
webhook → `storeInbound` → event → `processConversation`:
1. gate (mode / spam / rate limits / spend);
2. transcribe voice notes;
3. `runAgent` (tools; `<reply>` extraction; money, meta and language guards);
4. draft (default autonomy) or send.

Owner switch: "Bot on/off" in the admin header (`bot_settings.bot_on`). Off = the bot stays silent on Instagram; on = auto-paused chats go back to the bot and customers waiting from the last 2h get answered.

Test phase: the webhook drops every chat whose username isn't on the tester list (`src/lib/conversation/testers.ts`, admin Settings), so the real account can be connected safely. Rejected senders are cached in their own `bot_settings` row (`tester_denials`, never inside `testers`): "not on the list" until the list changes, a failed username lookup for 15 minutes only.

Approvals: `src/lib/approvals.ts` → admin `/admin/approvals` → `approval/decided`.
